# Архитектура

## Хранение и происхождение SVG

`assets/objects/{S|L}/{main|background}/{id}.svg` — исходные SVG, сохранённые побайтно. `assets/backgrounds/` — исходные фоны. `assets/library.json` хранит размеры, viewBox, цвета, SHA-256, исходный архив и имя файла для каждого элемента, плюс смысловые теги.

Каталог создан из экспортов отдельных объектов (8)/(9). Разбор больших листов на контуры не используется. Варианты из композиций не включены в основной каталог, чтобы не смешивать произвольные масштабы.

`build.cjs` встраивает только необходимые объекты и фоны в JSON внутри `ui.html` и `demo.html`. HTML самодостаточен; библиотека не загружается по сети.

## Подбор и композиция

`src/core.js` — независимый от браузера модуль. По названиям он сопоставляет русские/английские имена с ID. По смыслу используются тематические правила и основы слов, с объяснением выбора в интерфейсе. При отсутствии совпадений нет случайного выбора или генерации нового объекта.

`layout` располагает 1–5 предметов, вычисляет общий bounding box и **один общий scale** для всей композиции. Это сохраняет относительные размеры исходных объектов внутри набора. Формат и режим с местом под заголовок меняют допустимую область; вертикальная композиция использует меньше колонок.

Состояние сцены содержит `width`, `height`, `size`, `scale`, `palette`, `style`, `background` и элементы `uid/objectId/role/x/y/rotation`. Роли выбирают готовый SVG. Список элементов одновременно задаёт порядок слоёв. История хранит до 30 снимков состояния.

## Цвет и экспорт

Три тона фона и три объектных акцента задают явное соответствие исходной палитре. Меняются только атрибуты заливки/обводки; строки контуров `d` сохраняются. Монохромные варианты и фоны исходно содержат фоновые тона и не получают объектные акценты.

`serialize` создаёт один SVG с исходными path/rect и отдельной группой на каждый предмет. Перенос/поворот/масштаб записываются как transform. Идентификаторы clipPath и ссылки получают префикс объекта, чтобы дублирование не приводило к конфликтам. Корневой SVG задаёт размер холста; фоновый SVG масштабируется пропорционально с обрезкой по холсту.

Ни canvas-растеризации, ни image/base64-картинок в экспортируемом SVG нет. Пользовательская строка запроса не вставляется в SVG-разметку.

## Интерфейс и Figma

`src/app.js` управляет DOM, перетаскиванием, вводом, историей, файлами JSON и загрузками. `src/ui.html` — оформление. `src/code.js` — тонкий адаптер Figma: `createNodeFromSvg` импортирует сцену, `exportAsync` экспортирует выбранный пользователем фрейм после нативных правок.

Figma UI и адаптер общаются через `postMessage`; начальное рукопожатие включает доступные только в Figma кнопки. Manifest разрешает сеть только `none`. Внешние ключи, сервер и авторизация не используются.

## Возможное развитие

Для более широких метафор можно заменить только `select` языковой моделью: она должна возвращать ID из разрешённого каталога, а не SVG или новые изображения. Финальная раскладка и экспорт остаются детерминированными. В этой версии такого подключения нет.

## Три варианта и закрепление

UI строит три кандидата через `arrange` с разными стилями. Превью — отдельные SVG в img, поэтому их ID не конфликтуют с редактируемым холстом. Выбор кандидата сохраняет отменяемый снимок состояния. Любая ручная правка скрывает устаревшие варианты.

Флаг `locked` принадлежит экземпляру, а не типу предмета. При закреплении общий масштаб сцены сохраняется. Положение закреплённых экземпляров переносится точно; незакреплённые выбирают точки на сетке с оценкой пересечений, выхода за холст и расстояния от предпочтительной позиции. В оценке учитывается поворот. Это эвристика, не гарантия отсутствия пересечений. Смена холста/S/L при закреплении отклоняется явной ошибкой.
